# 00 · 总览：目标、非目标与基本约定

本文是整个设计文档集的入口。它定义 TermCore "是什么 / 不是什么"、统一术语、说明编程模型、
划定 v1 范围与里程碑。所有后续文档都以本文的约定为前提。

---

## 1. 定位

TermCore 是**终端 TUI 的底层 API 库**：用 C11 编写、导出稳定 C ABI、跨平台。
它向上层暴露的是终端原语，而不是应用框架：

- 控制终端（raw mode、alternate screen、光标、尺寸、信号）
- 拉取输入事件（键盘、鼠标、焦点、粘贴、resize）
- 绘制单元格（surface 双缓冲 + 差异提交）
- 处理 Unicode 文本（解码、字符簇、宽度、测量）

它提供机制，不提供策略：只给原语与能力检测结果，上层库（widget / 布局 / 组件）建立在它之上。

---

## 2. 目标（v1 必须做到）

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 跨平台行为一致 | 同一份 demo 在 Linux、macOS、BSD 的各类终端上行为一致 |
| G2 | 稳定 C ABI | 公开头只暴露不透明句柄 + POD + 函数；POD 字段只追加不重排 |
| G3 | 正确的 Unicode 渲染宽度 | 完整 UAX#29 字符簇；emoji ZWJ、变体选择符、区域指示符、组合符均按簇计算宽度 |
| G4 | 正确的输入解码 | 严格 UTF-8 解码（拒绝 overlong / 代理区 / 截断）；完整鼠标与 resize 支持 |
| G5 | 同步、可预测 | 无隐式线程、无隐式事件循环；`tc_present()` 的开销可预测 |
| G6 | 每帧零分配 | `tc_present` / `tc_get_event` / `tc_text_*` 路径上不调用 allocator |
| G7 | 崩溃安全 | 进程退出、崩溃、信号终止时终端状态可恢复；`tc_term_leave` 幂等 |
| G8 | 可离线测试 | 无 TTY 环境可完整跑通：注入输入 + 输出捕获 + 帧断言 |
| G9 | 零强制依赖 | 默认构建不链接第三方库；ICU 仅为可选后端 |

## 3. 非目标（明确不做）

| 非目标 | 说明 |
| --- | --- |
| **字体选择** | 库不参与字体选择、字形渲染、字号与 DPI；终端用哪种字体由用户与终端决定 |
| **终端选择** | 库不选择、不启动、不检测"应该用哪个终端模拟器"；它只识别**当前**终端具备哪些能力并据此降级 |
| widget / 布局 / 组件 | 不属于底层 API，留给上层库 |
| 事件循环 | 不内置；调用方自写循环与分发 |
| 输入事件回调 | 不提供事件回调注册（渲染变更回调另论，见 §5） |
| 网络 / 序列化 | 库只给不可变帧视图，传输与编码由外部工具负责 |
| bidi / shaping | 不做双向文本排版与复杂字形整形（如阿拉伯语、梵文整形） |
| 多进程 / 远程终端 | v1 只处理本进程的标准输入输出句柄（或显式注入的源与 sink） |

> "字体与终端选择由用户负责"是硬性边界：库对字体与终端类型**零策略**，只对"已连接的终端能力"做检测与降级。

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| **term** | `tc_term_t*` 句柄。一个终端会话：持有后端、能力位集、解析器、事件队列、输出通道 |
| **surface** | `tc_surface_t*` 句柄。离屏单元格缓冲（绘制目标），可绘制，不直接写出 |
| **cell** | 一个终端字符格。包含字符内容（UTF-8 簇字节）与属性（前景 / 背景 / 样式 / 宽字符标记） |
| **grapheme / 字符簇** | 用户感知的"一个字符"，可能由多个码点组成（如 `é` = `e` + U+0301，👨‍👩‍👧 = 多码点 ZWJ 序列） |
| **codepoint** | Unicode 码点（UTF-8 解码后的 U+XXXX） |
| **EAW** | East Asian Width。决定码点是窄（1 列）还是宽（2 列） |
| **Ambiguous** | EAW 中的 A 类码点（如 `…`、`±`），在东亚 locale 下宽、其它环境窄；宽度策略可配置 |
| **列宽 / columns** | 一段文本在终端上占据的单元格列数 |
| **raw mode** | 关闭行缓冲与回显、关闭信号字符处理，使按键直接可读 |
| **alternate screen** | 备用屏幕缓冲区；进入后不污染用户回滚历史，退出时恢复 |
| **DA** | Device Attributes 查询（`ESC [ c` / `ESC [ > c`），用于探测终端能力 |
| **terminfo / termcap** | 终端能力数据库；按 `TERM` 名称索引 |
| **SGR** | Select Graphic Rendition（`ESC [ ... m`），用于颜色与样式 |
| **SGR 1006** | 鼠标扩展模式，可报告大于 223 的坐标，是 v1 的鼠标主路径 |
| **Kitty 键盘协议** | 渐进式键盘协议，可区分更多修饰键组合、支持按键释放事件；失败时降级到传统序列 |
| **括号粘贴** | 终端把粘贴内容用 `ESC [ 200 ~` / `ESC [ 201 ~` 包裹，使应用区分"粘贴"与"键入" |
| **present** | 显式提交一帧：diff → 生成序列 → 广播 sink → 单次 flush |
| **diff** | 比较 surface 当前内容与终端已知状态，只输出变化部分 |
| **sink** | 输出目标。真实终端是一个内置 sink，此外可挂载任意数量的捕获 / 自定义 sink |
| **source** | 输入来源。默认是终端句柄，可被外部 vtable 完全替换 |
| **headless** | 无 TTY 的运行模式：无终端控制、输入靠注入、输出靠捕获 sink |
| **运行时开关** | 可在运行期开 / 关的终端特性（鼠标、焦点、括号粘贴、Kitty、同步更新、raw、altscreen）；options 里同名字段只是**初始值** |
| **初始化属性** | `create` 时冻结、运行期不可改的属性（headless、能力探测、文本模式、超时与容量、分配器） |
| **特性列表（profile）** | 能力位集 + **逐项来源**（默认 / 推断 / 查询 / 显式覆盖 / 用户探测）+ 环境指纹；可整体读写并序列化存盘复用（见 `03` §10） |
| **探测（probe）** | 无法确定时的人机交互体检：库提供每项的样例渲染与判定，应用渲染向导 UI 让用户确认，结论写回能力位集（见 `03` §11） |
| **注入输入** | 测试或工具经 `tc_term_inject_input` / 注入队列喂入的字节序列，走**真实解析路径**（不是桩替身）；用于离线测试与录制回放 |
| **backend** | 平台适配层（`tc_backend` 虚表），封装各平台差异 |

## 5. 编程模型

三件事构成全部使用方式：**句柄式对象、主动拉取事件、显式提交一帧**。

| 概念 | TermCore | 说明 |
| --- | --- | --- |
| 会话句柄 | `tc_term_t*` | 不透明；`tc_term_create(opt, &out)` 创建，`tc_term_destroy` 严格配对 |
| 绘制目标句柄 | `tc_surface_t*` | 不透明；离屏单元格缓冲，可反复绘制并提交 |
| 进入 / 退出 | `tc_term_enter` / `tc_term_leave` | `enter` 开 raw / altscreen / 鼠标 / 焦点并注册恢复钩子；`leave` 幂等 |
| 等待 | `tc_wait_event(term, timeout_ms, &ready)` | `0` = 非阻塞（推荐）；`> 0` OS 级等待；库不 sleep / 不忙等 |
| 窥视 / 取走 | `tc_peek_event` / `tc_get_event` | 不取走 / 取走一条；调用方自写 `switch` 分发 |
| 事件结构 | `tc_event`（kind + 联合） | 结构化字段，不用"参数位"式整数编码 |
| 字节 → 事件 | 解析器状态机 | 序列解码与归一化 |
| 尺寸 | `tc_term_get_size` / `TC_EV_RESIZE` | 行列尺寸 |
| 绘制 | `tc_surface_fill_rect` / `draw_text` | 单元格级原语 + 批量辅助 |
| 提交 | `tc_present(term, surface)` | 同步阻塞：diff → 生成序列 → 广播 sink → 单次 flush |
| 错误 | `tc_status` | 仅返回码，不提供"取最后一次错误" |
| 输入事件回调 | **不提供** | 输入事件一律拉取 |

**一处刻意的例外**：渲染变更（不是输入事件）可用 `tc_set_change_sink` 订阅回调。
这是为了满足离线测试与外部工具的增量通知需求；输入事件仍然只拉取、不回调。

## 6. v1 范围

### 6.1 五层能力

1. **控制层**（`docs/02-api-control.md`）
   - raw mode / cooked mode 切换
   - alternate screen 进出
   - 光标显隐、形状、位置
   - 窗口尺寸查询与 resize 事件
   - SIGWINCH、CTRL_C 事件化
   - 标题设置、退出与崩溃恢复、headless 创建
2. **能力检测层**（`docs/03-api-capability.md`）
   - `TERM` / terminfo / termcap、DA 查询、环境变量覆盖
   - 能力位集 → 颜色与特性降级
3. **输入解析层**（`docs/04-api-input.md`）
   - 严格 UTF-8 解码、序列状态机、Kitty 协议与降级
   - 完整鼠标、焦点、括号粘贴、ESC 超时、resize
   - 注入队列与外部 source 接管
4. **文本引擎**（`docs/05-text-engine.md`）
   - ASCII / Unicode 双模式、UAX#29 簇、EAW 宽度、测量 / 截断 / 换行点
5. **输出渲染层**（`docs/06-api-render.md`）
   - cell 与颜色样式、批量绘制、簇占位、行级 diff、`tc_present`、多 sink、变更回调、帧视图

### 6.2 交付物

- C 头文件（公开 API）
- 静态库：`termcore.lib` / `libtermcore.a`
- 示例 demo（事件打印器、鼠标演示、色板、滚动区、Unicode 宽度演示）
- 单元测试（纯逻辑单测 + 注入输入端到端）
- 本文档集

## 7. 设计原则

| 原则 | 含义 |
| --- | --- |
| **P1 机制而非策略** | 提供原语与检测能力，不替用户决定"用哪个终端""用哪种字体""怎么布局" |
| **P2 句柄不透明** | 公开 API 只有不透明句柄 + POD + 函数；内部结构可随版本演进 |
| **P3 显式优于隐式** | 显式拉取事件、显式提交帧、显式注入、显式挂载 sink；无隐式线程与隐式循环 |
| **P4 每帧零分配** | 热路径（`tc_present` / `tc_get_event` / `tc_text_*`）绝不分配；控制面才允许分配 |
| **P5 失败可降级** | 能力探测失败一律保守降级；单个 sink 失败不中断其它 sink；探测不得阻塞启动 |
| **P6 崩溃安全** | 任何路径退出都要恢复终端；`tc_term_leave` 幂等 |
| **P7 可离线验证** | 无 TTY 也能完整测试：注入输入、捕获 sink、帧断言 |
| **P8 ABI 稳定优先** | POD 字段只追加；函数只增不改；版本宏与符号可见性从第一天就设计好 |
| **P9 单线程** | 句柄不跨线程共享；所有回调在调用方线程同步执行 |
| **P10 零强制依赖** | 默认内置表；ICU 只是可选后端，数据不打包进二进制 |

## 8. 生命周期总览

```
tc_init_term_options(&opt)       填充默认 options
        │
tc_term_create(&opt, &term)      创建句柄（尚未改动终端）
        │
tc_term_enter(term)              进入：raw / altscreen / 鼠标 / 焦点 / 恢复钩子
        │
   ┌────▼───────────────────────────────────────────────┐
   │  调用方循环（库不提供）：                            │
   │    tc_wait_event(term, timeout, &ready)             │
   │    while (tc_get_event(term, &ev, &has) && has)     │
   │        switch (ev.kind) { ... }                     │
   │    绘制：tc_surface_*                               │
   │    tc_present(term, surface)   同步阻塞提交一帧      │
   └────┬───────────────────────────────────────────────┘
        │
tc_term_leave(term)              离开并恢复（幂等，atexit / 信号钩子同样调用）
        │
tc_term_destroy(term)            释放句柄
```

约束：

- 未 `enter` 时不允许 `present`（返回 `TC_ERR_STATE`）
- `leave` 可重复调用；`destroy` 会自动 `leave`
- 回调（变更回调、sink 回调）内**禁止**调用 `tc_present` 或写 surface

## 9. 里程碑

| 里程碑 | 内容 | 出口标准 |
| --- | --- | --- |
| **M1 骨架 + 控制层** | 构建系统、`tc_term_create/enter/leave/destroy`、raw mode、altscreen、光标、尺寸、信号事件化、崩溃恢复 | 目标平台上 demo 能进入并安全退出；异常退出可恢复终端 |
| **M2 能力检测** | terminfo / termcap 解析、DA 查询、环境变量、能力位集、降级矩阵 | 在 xterm / tmux / `TERM=dumb` / 未知 TERM 下均得到合理能力集，且不阻塞启动 |
| **M3 文本引擎** | 双模式、UAX#29 簇、EAW 表、测量 / 截断 / 换行点、UCD 生成脚本 | UAX#29 官方测试与宽度用例全绿；纯函数零分配 |
| **M4 输入解析** | 解析器状态机、键鼠事件、焦点、粘贴、resize、注入与接管 | 边界用例（不完整序列、超时、无效 UTF-8、粘贴含控制字符）全绿 |
| **M5 渲染 + 可测试性** | surface 绘制、diff、`tc_present`、多 sink、变更回调、帧视图、headless、demo | 无 TTY 环境下端到端可断言；真机 demo 表现一致；性能达标 |

## 11. 关键决策摘要（ADR 摘要）

| # | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| A1 | 语言 | C11 裸 C + 稳定 C ABI | 底层库定位，便于跨语言绑定 |
| A2 | 平台 | 多平台后端，差异封装在 `tc_backend` | 上层只见字节流、尺寸与能力位集 |
| A3 | 并发 | 同步；事件拉取；渲染显式 present | 可预测，易接入任意主循环 |
| A4 | 事件分发 | 只拉取，不做事件回调 | 用户明确选择 |
| A5 | 事件结构 | kind + 联合 | 类型安全、可读、易绑定 |
| A6 | 绘制模型 | surface 句柄 + 显式 present | 不做配对式绘制，提交点唯一可预测 |
| A7 | 错误 | 仅 `tc_status`，无 last error | 用户明确选择 |
| A8 | 命名 | snake_case + `tc_xxx_t` + `TC_` 常量 | 用户明确选择 |
| A9 | options | 库函数默认填充，无 cb_size | 用户明确选择 |
| A10 | 绘制粒度 | 单元格级 + 批量辅助 | 用户明确选择 |
| A11 | 内存 | 可注入 allocator，无裸 malloc | 用户明确选择 |
| A12 | 多输出 | 多 sink 并存广播 | 用户明确选择 |
| A13 | 输入 | 注入队列 + source vtable 并存 | 用户明确选择 |
| A14 | 增量通知 | 回调订阅 `tc_set_change_sink` | 用户明确选择，仅限渲染变更 |
| A15 | 全量帧 | 只读零拷贝视图 | 用户明确选择，网络由外部负责 |
| A16 | 文本引擎 | 独立公开 `tc_text_*`，完整 UAX#29 | 用户明确选择 |
| A17 | ASCII 模式 | 严格 7bit + 替换字符，宽度恒 1 | 用户明确选择 |
| A18 | 排版辅助 | 测量 / 截断 / 换行点；ICU 可选 | 用户明确选择 |
| A19 | 字体与终端 | 由用户负责，库零策略 | 用户明确要求 |
